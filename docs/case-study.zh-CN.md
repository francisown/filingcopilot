# 案例研究：一个“证据优先”的公司披露研究 Agent

**摘要。** FilingCopilot 是一个本地优先的公司披露研究工作台。它回答 SEC 文件相关问题、计算财务指标，并返回每个答案背后的证据。项目最有说服力的验证结果不是一个跑分，而是：**116 条数值声明与 SEC CompanyFacts 或独立算术检查完全一致，0 条不一致**；同时，每个保存的答案都可以导出为冻结证据包，并在离线状态下被另一个人复核。限制同样明确：140 题评测是自评的，没有独立人工金标准；使用模型的题目 P95 延迟为 417 秒。

这份案例研究说明做了什么、证据层如何工作、评测证明了什么和没有证明什么，以及下一步该做什么。

## 问题

公司年报很长、重复度高、数字密集。一份 10-K 可能有几百页；同一个指标会出现在多张报表、多个期间、不同币种和不同文件版本里。通用聊天机器人可以给出流畅的回答，但分析师真正需要的是：

- 这个数字来自哪份文件、哪一段？
- 它是年度、季度还是 TTM？
- 是报告币种还是折算币种？
- 计算使用的期间和单位是否一致？
- 换一个模型、换一台机器、换一个索引之后，复核者还能重新跑一遍吗？

这些问题是产品本身，模型只是其中一个部件。

## 它做什么

用户选择公司和 as-of 日期，然后用中文或英文提问。系统有两条路径：

1. **只看数据（Data only）。** 明确的年度数字、增长率、利润率和财务趋势不需要 LLM，直接确定性计算，离线可用、速度快。
2. **AI 研究（AI research）。** LangGraph Agent 规划任务、检索文件段落、调用财务工具、起草答案，并把声明提交给验证层。结果带引用，也明确列出证据缺口。

每个答案都能打开到原始段落。研究结果可以导出为证据包，里面包含问题、声明、引用、计算、源文件哈希和包哈希。独立验证器不需要研究 Agent、不需要模型、不需要网络，就能重新检查这个包：源文件变了，文档哈希失败；引用被改了，原文跨度检查失败；包被改了，包哈希失败。

同一套服务通过浏览器工作台、CLI、REST API 和 **30 个 MCP 工具**暴露。四个入口的意义不是功能数量，而是无论问题从哪里来，证据规则都相同。

## 架构

流程刻意保持简单：

```
Web / CLI / REST / MCP
        |
   研究服务
        |
  能力计划与预算
        |
  LangGraph 工具 Agent
        |
  混合检索：SQLite FTS5 + 可选本地向量
        |
  证据账本：段落、事实、计算、源哈希
        |
  确定性数值门 + 叙述门
        |
  答案 + 明确缺口
        |
  冻结证据包 + SHA256 清单
        |
  离线验证器
```

两个设计选择比框架选型更重要。

**第一，事实来源是证据账本，不是聊天记录。** 一个事实带有公司、文件、公开日期、报告期间、币种、单位、源 URL 和定位符；一个计算带有输入和公式；一个段落带有章节和行号。答案由这些对象组装，所以引用是指向已存对象的指针，而不是模型临时生成的字符串。

**第二，验证是分层的。** 数值检查重算数值，并与 SEC CompanyFacts 或独立算术路径比对；叙述检查拒绝明显的币种方向冲突，以及“从选段推断整份文件没有提及”的越界；语义审查再检查主语、方向、期间、重大性和证据范围。语义审查仍然是模型判断，通过它不等于正确，所以证据包还会暴露缺口和审查状态。

更完整的架构说明见 [`docs/architecture.md`](architecture.md)，独立验证器见 [`docs/independent-verifier.md`](independent-verifier.md)。

## 评测

评测把四个经常被混成一个“准确率”的问题拆开：流程有没有交付答案？财务计算对不对？检索有没有找到正确段落？叙述有没有超出证据？

记录在案的运行使用 **140 道未修改的双语问题**：100 道研究题和 40 道边界题。知识日期是 2026-10-08，语料包含 62 份文件、1,166 条事实、39,912 条报表事实和 31,123 个段落，运行使用冻结的源码快照。

| 问题组 | 完整 | 部分 | 无研究答案 |
|---|---:|---:|---:|
| 数值（20） | 20 | 0 | 0 |
| 原因（20） | 14 | 6 | 0 |
| 否定检查（20） | 16 | 4 | 0 |
| 风险（20） | 11 | 8 | 1 |
| 年度比较（20） | 20 | 0 | 0 |
| **研究题（100）** | **81** | **18** | **1** |

另外 40 道题问的是不受支持的未来价格保证或假设性的行情源故障。40 道全部给出了具体边界解释，且没有调用模型。运行器把它们记为 `abstained`，它们不是 40 个失败的模型答案。

这次运行有 60 道题使用了模型，发起 476 次 HTTP 请求，记录 442 次 HTTP 200，报告 4,312,447 tokens。使用模型的题目中位延迟 92.79 秒，P95 为 417.11 秒。总体中位数 0.075 秒是被 80 道零模型题拉低的，不能代表研究延迟。

数值 oracle 找到 **116 条与 SEC CompanyFacts 或算术检查完全一致的声明，34 条超出该检查器范围，0 条不一致**。34 条未评估的声明不计为正确。保存的证据包与可用原始源做了审计：100 个一致，没有缺失源。记录在案的源码通过了 **1,656 个测试**；当前分支 **1,718 个全部通过**（包含新增的信贷风控 demo 测试）。

检索分两层测量。内部的 200 题精确段落金集是回归集，衡量的是严格段落命中，不是人工相关性；对外汇报用下面的产品 scope 外部测试。

**外部检索更新（2026-10-23）。** 之前的 FinanceBench 全局语料测试作废：它忽略了产品实际使用的“选定公司” scope。evidence-page 采用 company+year、section-aware 3000 字符切块、4000 字符父窗口和 title-based top1 rerank：**page hit@5 0.920、page@1 0.707、snippet hit@5 0.920、answer-supported top1 0.427、MRR 0.798**。full-filing 解析 61 份 PDF、113 道题：**page hit@5 0.850、page@1 0.478、snippet hit@5 0.858、MRR 0.624**；新增文档 22 题 held-out page hit@5 为 0.773。这些是检索测量，不是答案准确率或人工相关性。详见[FinanceBench 报告](financebench-scoped-2026-10-23.md)。

叙述声明方面，对 40 条已交付声明的人工初查记录为 95% 支持、5% 不清楚、0% 不支持。审查者是项目作者本人，不是领域专家；样本从已交付声明中选取，因此不包含被拒绝的草稿和拒答。独立领域审查仍未完成。

### 评测证明了什么

- 流程能在 100 道研究题中为 99 道给出完整或部分答案，其余明确列出缺口。
- 确定性数值检查能用一个外部源验证一个有意义的子集，且在该子集内 0 条不一致。
- 证据包可以被离线重放和审计。
- 失败模式是可见的，并且有回归测试覆盖。

### 评测没有证明什么

- 没有证明通用答案准确率。没有独立人工金标准。
- 没有证明每条叙述声明都有证据支持。模型审查不等于人工审查。
- 没有证明生产可用。延迟、成本和发行商覆盖都还达不到生产级。
- 没有证明人工相关性或答案准确率：evidence-page 为 0.920 page hit@5 / 0.920 snippet hit@5，full-filing 为 61 份已解析 PDF 上的 0.850 / 0.858；新增文档 22 题 held-out page hit@5 为 0.773。

## 失败分类

最有价值的工程产出不是通过数，而是失败清单。五个例子：

**1. 工具参数被字符串化。** 工具收到 `"5"` 而它期望 `5`，在实时运行中触发检索 `TypeError`。修复：分派前归一化明确的整数/布尔字符串参数。回归：聚焦测试加已捕获的检索重放。

**2. 美元/汇率方向反转。** 语义审查接受了一条把汇率影响方向写反的声明。原文说外币走弱、美元走强可能提高国际价格并降低需求，草稿写反了。修复：在语义审查前增加窄范围的币种方向冲突检查。回归：重放已捕获的失败判定，现在会拒绝该声明。

**3. 从选段推断整份文件没有提及。** 草稿因为选中的段落没有提到某个风险，就推断整份文件没有讨论。修复：拒绝基于选段的“整份文件不存在”声明，同时保留直接披露的否定事实。回归：已捕获的否定案例现在在语义批准前失败。

**4. 用纯数字回答原因/风险问题。** 草稿用数字回答“为什么利润率变化”，没有解释。修复：原因或风险请求不能只靠数字完成；有效数字保留，同时标记解释缺口，修复预算可以补充文字。回归：聚焦完整性测试。

**5. 回退路径重复事实。** 无提交回退把同一个财务观察重复了三次。修复：只在无提交回退中合并完全相同的观察，且发生在正常验证之后，同时保留不同数值、期间、币种、概念和明确的源/版本请求。回归：一个失败案例加九个控制案例。

第六个较小的问题是边界响应的英文回退文案不完整。修复：补全文案并增加本地化测试。列出这些不是为了自嘲，而是因为每个失败都变成了一个持久检查。

## 治理与模型风险视角

这个项目不是一个经过认证的模型，也不应被解读为监管批准。但证据层能对应到 SR 11-7 风格验证中审查者会问的问题：

| SR 11-7 关注点 | 项目证据 |
|---|---|
| 概念合理性 | 确定性数值门、有文档的叙述门、明确限制 |
| 数据血缘 | 文件 accession、源 URL、公开日期、期间、币种、单位、文档哈希 |
| 可复现性 | 冻结输入、规范化的包、SHA256 清单、独立验证器 |
| 人工审查 | 声明级审查状态；独立审查明确标注待完成 |
| 持续监控 | 冻结评测集、检索金集、负面结果报告、回归测试 |
| 局限性 | 公开召回、延迟、成本、覆盖和自评限制 |

对银行来说，有用的不是“模型很聪明”，而是“模型的输出能追溯到源、能被重跑、能被质疑”。这和验证工作底稿是同一种直觉。

## 下一步

1. **独立人工审查。** 找 2–3 位信贷风险或金融分析审查者，盲审一批声明，公开分歧率。没有这一步，95% 的支持率只是自评。
2. **延迟与成本。** P95 417 秒和 4.3M tokens 不适合交互式使用。下一步是缓存、用更小的模型做抽取、并行工具调用，以及每个答案的硬性成本预算。
3. **信贷风控垂直案例。** 新增的 `examples/credit-risk` 已经把语料、段落、证据包和验证器复用到合成的政策与模型验证文档上。下一步是对这个垂直案例做独立审查，并扩大题集。
4. **检索。** evidence-page 达到 page hit@5 0.920、snippet hit@5 0.920；full-filing 在 61 份已解析 PDF 上达到 0.850/0.858。下一步是真正的 held-out split，以及 domain/earnings 的表格感知检索，而不是继续加大固定切块。
5. **覆盖。** 外国发行人、财报电话会和跨币种 ADS 桥接仍不完整。覆盖范围应该明确说明，而不是暗示。
6. **打包。** 验证器已经可以独立分发。下一步是给审查者一个小型 CLI，不需要安装完整应用就能运行。

## 复现

在项目环境已安装的前提下：

```powershell
# 离线检查证据包，不需要模型或网络
.\.venv\Scripts\python.exe -m filingcopilot verify-package examples/annual-facts.json

# 信贷风控垂直 demo，不需要模型或网络
python examples/credit-risk/demo.py demo

# 完整评测（使用模型的题目需要配置 API）
python -m filingcopilot evaluate --output artifacts/evaluation.json
```

记录在案的评测数据和限制见 [`docs/evaluation.md`](evaluation.md)，证据包协议见 [`docs/research-package-protocol.md`](research-package-protocol.md)。
