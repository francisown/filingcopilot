# 中文发布稿

## V2EX / 技术社区版

**标题：做了一个“证据优先”的财报 RAG Agent，答案可以离线复核**

最近把一个小项目整理开源了：FilingCopilot，面向 SEC 财报的研究工作台。它不是一个聊天框，重点在答案背后的证据层。

流程大概是：问题 → 研究服务 → LangGraph Agent 检索/调用财务工具 → 证据账本 → 确定性数值门 + 叙述门 → 答案和缺口 → 冻结证据包 → 离线验证器。

几个我觉得比较有用的设计：

1. 每个事实都带公司、文件、公开日期、报告期间、币种、单位、源 URL 和定位符；引用指向已存对象，不是模型现编的字符串。
2. 数值检查会重算，并与 SEC CompanyFacts 或独立算术路径比对；叙述检查会拒绝币种方向错误、从选段推断“整份文件没提”这类越界。
3. 答案可以导出为带 SHA256 清单的冻结包，离线验证器不需要 Agent、模型或网络，就能检查包哈希、文档哈希和引用原文跨度。
4. 纯数据路径不需要 LLM：年度数字、增长率、利润率、趋势都是确定性计算。

记录在案的评测：140 道双语题；100 道研究题里 81 完整、18 部分、1 无答案；116 条数值声明与 SEC/算术检查一致，0 条不一致；当前分支 1,718 个测试全部通过（记录源码为 1,656 个）。

弱点也说清楚：评测是自评的，没有独立人工金标准；检索 Recall@5 通过 coverage rerank 从 0.255 提到 0.430，但 growth/competition 仍然弱；使用模型的题目 P95 延迟 417 秒，4.3M tokens。这些数字都公开在仓库里，没有藏。

另外加了一个信贷风控垂直 demo：把同样的语料/段落/证据包/验证器复用到合成的信贷政策、模型验证报告和组合表现文档上，对应 SR 11-7 风格的“可追溯、可复跑、可质疑”。

仓库：https://github.com/francisown/filingcopilot

想听听大家对证据模型和评测设计的批评，尤其是：这种离线验证器对真实审查流程有没有用？

## 即刻 / 小红书版

**标题：大部分 RAG demo 只展示答案，我想展示“怎么证明”**

做了一个财报研究 Agent，最在意的不是回答多流畅，而是：

- 每个数字能追到哪份文件、哪一期、什么币种、哪一行；
- 答案能导出成带 SHA256 的证据包；
- 另一个人不需要模型、不需要联网，就能离线复核；
- 纯数字问题根本不用 LLM。

评测结果：140 道双语题，81/100 完整；116 条数值声明 0 条不一致。弱点也公开：自评、检索 Recall@5 0.430（coverage rerank，词法基线 0.255）、P95 417 秒。

还做了一个信贷风控版 demo：信贷政策、模型验证报告、组合表现，同一套证据层。

仓库：https://github.com/francisown/filingcopilot
