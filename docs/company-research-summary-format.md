# 公司研究模块总结

公司研究页有九个资料模块。每个模块按自己的问题生成短文，展示结论、证据、适用边界和待补信息。
模块定义集中在 [company_modules.py](../src/filingcopilot/company_modules.py)；
六主题完整报告使用独立的报告结构。

## 模块范围

| 模块 | 类型 | 内容 |
|---|---|---|
| `business` 商业模式 | 分析 | 产品、服务、分部、客户及收入来源。 |
| `operating_change` 经营变化 | 分析 | 年度与季度经营变化、已披露驱动及计划，分别注明期间。 |
| `cashflow` 现金流与资本投入 | 分析 | 现金生成、现金资本开支及其与利润的关系。 |
| `debt` 负债与流动性 | 分析 | 债务结构、到期安排、流动性和契约条件。 |
| `risk` 风险 | 分析 | 已披露的重要风险及可观察的相关事项。 |
| `recent_events` 近期事件 | 整理 | 知悉日期前取得的官方公告和外部更新。 |
| `valuation` 估值 | 分析 | 可用倍数、各自口径及待验证的假设。 |
| `ownership` 上市股份与币种 | 整理 | 股份类别、上市证券、币种及其配对关系。 |
| `audit` 审计报告原文 | 整理 | 审计师、意见、审计范围及原文限定。 |

分析型模块可以归纳所引披露，提交 `analysis` 声明。
整理型模块提交 `narrative` 声明，保留原文的期间和范围，不加入经营判断。

## 文章结构

1. **正文**：一至三段连贯短文，第一段先给主要结论，后续段落补充产品、客户、渠道、驱动或限制。中文每段最多 220 字，英文最多 300 字符。页面在正文中用 `[1]`、`[2]` 标记证据，不把“查看证据”按钮插在段落之间。
2. **边界**：正文之后说明适用范围和不能推出的结论。
3. **待补信息**：说明缺什么、影响哪部分判断及可怎样补充。
4. **证据清单**：文章末尾集中列出正文编号对应的原文、事实或计算；点击“打开证据”查看金额、单位、财务期间及公开日期。

关键数字由代码从已核验的证据中渲染。模型文字保持定性表述，不自行改写金额、比例或倍数；
财年、季度及日期标签可以保留。预取的相关数字若未被结论引用，会单独标明。

同一段落的引用应支持该段落的具体说法。所引摘录未提及某事，只能说明摘录范围内未见，
不能据此宣称整份申报没有披露。年度、单季、YTD、TTM 和时点资料分别使用，不跨口径支撑结论。

## 缺失和失败

有已核验结论时展示总结；无模型或模型失败但取得原文时，可展示原文材料；
没有可交付内容时，展示缺口和失败原因。局部来源失败不删除其他已核验内容。

模块会保留来源、预算或复核产生的缺口。格式约束与内容核验分别执行，
条数和长度合格并不等于结论得到来源支持。
估值模块展示计算和假设，不生成评级、买卖建议或股价预测。

## 实现位置

| 文件 | 职责 |
|---|---|
| [company_modules.py](../src/filingcopilot/company_modules.py) | 模块标题、类型、问题、关注点、限制、工具及缺失说明。 |
| [company_page.py](../src/filingcopilot/company_page.py) | 为页面提供模块定义与资料。 |
| [models.py](../src/filingcopilot/models.py) | 通过 `ResearchRequest.module` 标识本次模块。 |
| [agent.py](../src/filingcopilot/agent.py) | 将对应写作要求加入研究过程，约束提交格式。 |
| [verification.py](../src/filingcopilot/verification.py) | 复用普通研究的来源、范围、数字及语义检查。 |
| [company-workspace.js](../src/filingcopilot/static/company-workspace.js) | 按模块发起请求，呈现文章、数字和引用。 |

修改模块时，应同步检查注册表、页面定义、研究请求和渲染结果。
[模块测试](../tests/test_company_modules.py)覆盖九个模块的映射、提示、提交限制及空结果。
前端检查使用 `node scripts/check_company_workspace_ui.cjs`。

历史现场记录仅保留在本地评估档案，不随公开仓库分发。
